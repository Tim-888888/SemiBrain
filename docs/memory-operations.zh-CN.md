# 长期记忆

[简体中文](memory-operations.zh-CN.md) · [English](memory-operations.md) · [返回中文首页](../README.md)

长期记忆由用户自主开启，只属于当前用户。agent-service 管理 `memories`、`memory_settings`、修订哈希与幂等记录；conversation 网关根据登录会话确定所有者和授权版本。

模型没有直接写入记忆的工具，系统也不会从未经核验的调查结论中自动提取记忆。

## 两个开关分别控制什么

| 设置 | 行为 |
| --- | --- |
| 记忆总开关 | 同时控制记忆调用与自动提取；关闭后保留已保存内容 |
| 自动提取 `auto_extract` | 单独选择是否生成待确认候选；已有账号缺省为关闭 |

关闭记忆总开关会使当前提取批次的代际标识失效，迟到的模型响应无法继续保存候选。重新开启后，只处理该次变更之后提交的消息。

**关闭记忆期间创建的新会话不会接收个人长期记忆。** 已有会话中的历史消息独立于该开关；关闭记忆不会删除当前对话上下文。

仅关闭自动提取，已确认记忆仍可被调用；关闭总开关则同时停止提取和调用。

## 自动提取的时机与频率

agent-service 所属的 `memory-worker` 使用独立 Celery 队列，在回答流程之外处理已完成的运行。

| 配置或行为 | 默认值 / 范围 |
| --- | --- |
| 延迟处理 | 等待 60 秒后处理 |
| 用户级提取间隔 | 每位用户最多每 300 秒发起一次批量提取处理 |
| 单批范围 | 同一个会话中最多 8 个已完成运行 |
| 提取模型 | 默认 `deepseek-flash`，可通过部署配置选择批准的模型 |
| 模型或解析失败 | 最多重试三次；超过后记录受影响输入的处理检查点和仅含元数据的失败日志 |

延迟、间隔与模型配置见 `.env.example`。批量调度间隔不等于包含失败重试在内的绝对请求次数上限。系统在回答和发布主流程中不发起记忆提取模型请求。

运行处理检查点、带租约的用户提取代际标识，以及事务化候选发布，使重复唤醒和重试能够安全处理。

## 提取哪些内容

仅提议用户**明确表达的长期偏好与工作背景**。助手回答、工具结果和文档都不作为提取输入。包含凭据的用户消息和过长的粘贴内容会被跳过。

每条候选包含用户原话，以及经授权的用户消息来源哈希。确认和使用时会重新检查来源访问权限。模型输出必须通过验证，不能作为写入指令；待确认候选不能进入回答上下文。

## 候选确认与人工修改

“我的记忆”最多展示 50 条待确认建议，支持查看、编辑、确认和忽略。

- 确认更新时校验原记忆的修订版本，后台提取不能覆盖人工修改。
- 忽略后只保留指纹，用于抑制标准化后相同的建议。
- 写入候选或忽略候选不会使活动任务失效。
- 确认保存则遵循已有的有效记忆版本规则。

该功能不引入批量导出、向量搜索或话题跟踪。回滚时恢复先前的后端/Web 镜像并停止新增 worker；新增集合与字段保持向后兼容。

## 已确认记忆的内容与生命周期

“我的记忆”支持已确认的回答偏好、工作背景和报告摘录。报告摘录必须是当前用户有权访问的最终报告中的连续原文，并保留来源哈希与来源链路。

有效期需明确设置，最长一年；过期条目不再调用。修改会替换有效内容并保留修订哈希，不保留旧正文。删除只留下身份/修订墓碑并移除修订记录，不会追溯删除原始会话或已经交付的历史回答。

## 回答时如何使用

每位用户最多保存 100 条记忆，每次运行最多固定使用 5 条符合条件的记忆，偏好与工作背景优先。报告摘录需要与首轮问题存在词语重合。这是有数量限制的记忆调用，不是向量记忆检索。

记忆作为用户数据在上下文压缩之后加入，不进入提示词预览副本。上下文统计单列记忆类别。对话理解与证据审核调用不接收个人记忆内容；当前指令和后端授权始终优先于记忆文本。

快速问答、单 Agent 与多 Agent 共用同一记忆读取逻辑。所有者修订版本校验阻止已修改、删除、关闭或过期的记忆继续通过旧运行使用。受影响的运行会停止并提示重新提交。

每次使用前检查来源权限，并将来源加入最终报告的来源链路，避免已经撤回的资料借由记忆获得永久访问资格。该实现不要求额外引入第三方记忆数据库。
