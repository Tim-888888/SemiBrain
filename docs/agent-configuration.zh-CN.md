# Agent 配置与评测

[简体中文](agent-configuration.zh-CN.md) · [English](agent-configuration.md) · [返回中文首页](../README.md)

Agent 配置用于管理各角色的模型、补充指令、意图卡，以及用户侧多 Agent 选项的可用性。配置由 agent-service 管理；conversation 网关验证管理员身份并提供审计操作人，不接受客户端自行指定配置所有者。

## 可以配置什么

| 配置内容 | 作用与边界 |
| --- | --- |
| 角色文本模型 | 从部署已批准的文本模型名称与当前角色映射中选择 |
| 角色补充指令 | 补充该角色的工作要求，不替代核心规则 |
| 意图卡 | 在受限结构内帮助理解与分类任务 |
| 多 Agent 可用性 | 控制用户是否能为新请求选择多 Agent |

模型端点、凭据、协议、上下文限制、核心安全规则和实际工具权限仍由部署与代码管理。管理员不能通过此 API 输入新的模型端点或密钥。视觉推理继续使用单独部署的视觉模型配置。

## 草稿、审核与发布

1. 创建不可变且与在线配置隔离的草稿。
2. 发布时显式确认审核并填写原因。
3. 系统通过修订版本比较更新（CAS）和可执行基线指纹，防止并发覆盖或不兼容发布。
4. 发布命令保持幂等，并记录审计信息。
5. 新受理的运行复制已发布设置，包括模型配置与版本标识；专业子任务继承该快照。

一次运行中的稳定系统提示词前缀因此保持不变。切换当前配置不会改写正在执行的任务。代码升级保留已审核的补充说明和意图卡；不兼容的检查点恢复仍会被可执行版本校验拒绝。

回滚可以选择此前发布过的版本，或当前内置基线。

## 意图卡与执行模式

意图卡辅助分类，不会凭空增加用户必须完成的目标，也不负责决定是否启用多 Agent。快速问答、单 Agent 和多 Agent 共用已发布的意图卡及角色补充指令。

部署层禁用多 Agent 时，该限制优先于配置开关。配置开关影响新请求，不会取消已经受理的任务。自由 Markdown 输出与服务端权限、证据校验机制保持不变。

## 评测面板怎么看

面板展示当前管理员最近的 50 次运行：

| 指标或记录 | 口径 |
| --- | --- |
| Token 用量 | 来自模型提供方的实际用量回执，缺失用量单独标记 |
| 运行状态 | 来自持久化执行记录 |
| 耗时 p95 | 展示样本运行耗时的第 95 百分位数 |
| 人工审核结果 | 由人工记录质量判断 |
| 路由 macro F1 | 仅在填写了预期路由动作的已标注样本上计算 |
| 人工核验的证据支撑比例 | 排除尚未检查的记录 |

模型自评分和任务执行状态都不能直接作为事实质量结论。面板中的近期样本也不是冻结的独立基准测试集。

未配置价格时，货币成本显示为未知，不把 Token 数量当作费用。评测结果的修改同样具有 CAS、幂等与审计记录。
