# 报告导出

[简体中文](report-export.zh-CN.md) · [English](report-export.md) · [返回中文首页](../README.md)

进入成功或部分完成终态的回答，均可导出为 Markdown、Word 和 PDF。网关确认所有者权限后，向 agent-service 获取不可变的报告；business-service 转换报告原始内容，不调用模型重写回答，也不接受浏览器提交的 HTML。现有 Markdown 和报告协议保持不变。

## 创建导出与下载

| 接口 | 用途 |
| --- | --- |
| `POST /v1/runs/{run_id}/exports` | 仅接收请求 UUID 与导出格式，创建持久化、幂等的任务 |
| `GET /v1/runs/{run_id}/exports` | 页面刷新后恢复最近的导出任务 |

导出任务固定报告 ID、修订版本、内容哈希与渲染器版本。下载使用已有的认证资产代理，重新检查所有者认证代际、来源权限、报告哈希、最终有效的发布任务和过期时间。

来源被撤回后，后续导出与下载也会被阻止；已经下载到用户设备的文件无法追溯收回。

## 任务、恢复与清理

`report_exports` 和 `report_export_owners` 归 business-service 管理，不存在跨服务数据库访问。

| 项目 | 约束 |
| --- | --- |
| 任务租约 | 带并发隔离校验的 150 秒租约 |
| 崩溃恢复 | 最多两次恢复尝试 |
| 用户未完成任务 | 每位用户最多同时保留三个未完成导出 |
| 文件有效期 | 30 天；任务元数据继续保留用于审计 |

任务共用队列排空控制。普通转换失败会明确终止，用户可重新申请导出。对象上传前先登记上传意图，使崩溃留下的对象仍可回收。清理先移除对象，再移除资产元数据，并保留最终有效的发布结果。

## Word

Word 使用 python-docx 和 Markdown token 生成，保留标题、正文、列表、表格、引用与代码块，并附加引用标记。公式语法保留为原始文本。

仅嵌入回答实际引用、且存在于服务图片注册表中的图片，并在嵌入前实时校验资产权限。未知图片使用替代文本占位；不执行远程图片加载、脚本或 HTML。

## Markdown 与图片打包

不含图片时，保持 Markdown 源字节不变，下载为 `.md`。含图片时，下载为包含文档和 `images/` 目录的 ZIP。

已注册图片会重新授权，并以内容寻址的名称保存；Markdown 图片地址改为相对路径。离线打开前需要解压整个包。位图统一规范为 PNG，保留透明通道；SVG 使用已有的惰性图片校验器。

支持行内图片与引用式图片语法，代码示例和被转义的图片语法保持不变。未知或无权访问的图片会使导出明确失败，避免悄悄生成缺图文件包。不请求远程 URL。

## 下载引用来源

引用来源下载使用 `GET /v1/assets/{asset_id}/download?version={document_version}`。该新增接口将 Markdown 来源与绑定该版本的已注册图片一起打包，最多 50 张图片、32 MiB；其他文件类型保持原有行为。

原始 Markdown 图片地址通过 `original_ref` 解析，经过审核的 Markdown 则通过注册的资产 URL 解析。来源资产必须属于指定的已发布版本。没有版本信息的历史引用仍解析到其精确的来源资产，不替换成更新的正文。

每个资产读取前以及文件包返回前都会校验权限。来源文件包按需生成，不产生永久衍生文件或新数据库记录。`/content` 继续维持现有字节读取和预览行为。

## 按用户要求自动交付文件

单 Agent 和多 Agent 调查都会在理解阶段区分内容工作与交付方式：

- 要求把最终回答保存成 Markdown 时，使用 `delivery.method=report`；独立的纯文件目标可以另行标记。
- 混合内容编辑与交付要求的目标会被完整保留，不会删除交付部分后留下空任务。
- 运行时保留原目标并检查内容义务；规划器不能再委派一条重复撰写 Markdown 的分支。
- 指定 Skill/程序输出及数据文件继续使用 `method=tool`，仍要求有成功登记的产物。
- 旧检查点默认使用工具交付。

Agent 在提交不可变报告和 `report.ready` 事件的同一事务中，提交可选的 `answer_export` 意图。conversation 投影将工作保存在自身的 `gateway_runs` 记录中。

conversation worker 使用基于 report/run 的稳定幂等键，调用已有的 business 导出 API 并轮询任务，不增加模型请求。索引支持查找待处理任务；带并发校验的 90 秒租约、连续三次服务失败与十分钟截止时间，共同约束恢复流程。处理时会重新校验当前所有者授权。

回答内容状态与导出状态独立。交付失败时回答仍然可读，用户可手动重试。前端自动展示生成/下载状态，重新打开历史记录时可恢复该状态。不新增存储服务或跨服务数据库写入。

## PDF

PDF 使用已有的断网 Docker/LibreOffice 运行环境，将生成的 DOCX 转换为 PDF。运行环境包含中日韩字体，使用固定命令、28 秒执行时限，并无条件执行清理。不引入新的沙箱提供方。

| 限制 | 上限 |
| --- | --- |
| 文本 | 64,000 个字符 |
| 图片数量 | 12 张 |
| 输入图片总量 | 12 MiB |
| 输出文件 | 16 MiB |

超限会明确报错，不截断回答后继续导出。
