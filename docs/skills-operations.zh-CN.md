# Skills 审核、发布与执行

[简体中文](skills-operations.zh-CN.md) · [English](skills-operations.md) · [返回中文首页](../README.md)

管理员在 **Skills** 页面创建不可变的草稿版本，发布时需要明确确认审核并填写说明。向知识库上传文档不会自动注册 Skill。

## 一个 Skill 包含什么

| 内容 | 用途 |
| --- | --- |
| 简短目录描述 | 让 Agent 判断能力是否适合当前任务 |
| Markdown 指令 | 描述工作方法与步骤 |
| 依赖项 | 声明运行所需能力 |
| 账号与 Agent 角色权限 | 限定可使用该能力的身份与角色 |
| 可选的已审核 Python 代码 | 执行确定性的处理逻辑 |
| 参数 schema、固定导出文件名 | 约束输入与可登记的输出 |
| 执行时限 | 脚本运行限制为 1–30 秒 |

## 按需加载与调用

目录仅展示元数据。Agent 通过 `skill.load` 获取指令和固定版本，再通过 `skill.execute` 提交 JSON 参数，以及已授权的输入资产、查询或回答标识。执行接口不接受调用方临时提交代码。

Skill 指令用于指导方法，不能充当事实证据，也不规定最终回答结构。脚本结果与可下载产物沿用已有的证据和授权处理流程。

## 版本与撤权

MongoDB 中按运行和角色固定 Skill 版本，防止新发布改变运行中的代码，或悄悄扩大能力范围。Docker 沙箱运行过程中会再次检查当前用户角色、Agent 角色、依赖项和启用状态。

禁用 Skill 会停止后续执行，并拒绝访问依赖该能力的产物。普通版本升级仍保留此前已发布结果的来源记录访问能力。

临时的运行版本绑定与加载回执使用七天 TTL 清理；已审核版本、命令审计记录和用户产物各自遵循独立的持久化生命周期。

## 沙箱与脚本边界

脚本在已有的断网、资源受限 Docker 沙箱中运行，只登记声明过的导出文件。依赖包必须预先存在于已批准的运行镜像中，Skill 不能在宿主机安装依赖。

管理员审核范围包括代码导入、参数和输出。审核是一道应用权限边界，不意味着任意代码已经获得形式化安全证明。已审核脚本保存在版本化记录中，不开放宿主机 Skill 目录，也不允许运行时安装包。

## Supervisor 与服务分工

Supervisor 获得各角色扩展元数据的并集，以便规划任务，但不会因此取得子 Agent 的执行权限。网关提供可信角色信息；business-service 管理配置、版本、执行与撤权。agent-service 不直接访问这些数据库记录。
