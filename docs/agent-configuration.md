# Reviewed Agent configuration and evaluation

Agent configuration is agent-service authority. The conversation gateway authorizes administrators and supplies the audit actor; it never accepts a client-supplied owner. Configuration contains approved text model selections per role, supplemental role instructions, bounded intent cards and availability of the user-facing multi-Agent option. Endpoints, credentials, protocols, context limits, core safety rules and actual tool authorization remain deployment/code concerns.

Drafts are immutable and isolated. Publication requires an explicit review and reason, uses revision CAS and checks the executable baseline fingerprint. Rollback accepts a previously published version or the current built-in baseline. Commands are idempotent and audited. Published settings are copied into each newly accepted run, including model profiles and version identifiers, and inherited by professional branches. Stable system prefixes therefore stay unchanged during a run; changing the active configuration does not rewrite an in-flight task. Code upgrades retain reviewed notes/cards, but incompatible checkpoint resumes continue to fail the existing executable version guard.

Model choices come from deployment-approved text model names and the current role mappings; an admin cannot enter a new endpoint or secret through this API. A deployment-level multi-Agent disable remains authoritative. The configuration switch affects new requests and does not cancel previously accepted work.

Intent cards assist classification; they do not introduce required user goals or select whether multi-Agent is enabled. Quick answers, single Agent and multi Agent use the same published cards and role additions. Free-form Markdown and the server-side permission/evidence checks stay in place. Visual inference remains the existing separately deployed vision profile.

The evaluation panel shows the current administrator's latest 50 runs, actual provider token receipts (with missing usage distinguished), durable execution states, elapsed-time p95 and manually reviewed outcomes. Optional expected route actions yield a macro F1 over only the labeled sample. Manually checked grounding ratios exclude unchecked rows. No model-generated self-score or execution status is treated as factual quality. These samples are not a frozen independent benchmark. Currency cost stays unknown without a configured price; token counts are not presented as money. Evaluation edits have CAS, idempotency and an audit trail.
