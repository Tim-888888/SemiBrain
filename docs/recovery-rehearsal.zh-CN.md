# 备份与隔离恢复演练

[简体中文](recovery-rehearsal.zh-CN.md) · [English](recovery-rehearsal.md) · [返回中文首页](../README.md)

运维脚本提供需要短暂维护窗口的**手动冷备份**，不负责定时备份，也不保证每日 RPO（恢复点目标）。仅在已授权的 Docker 主机上运行。

仅限 root 访问的备份包含凭据与容器配置，不得公开或放入 Web 根目录。需要应对整机丢失时，应另行授权创建加密的异机副本。

## 1. 准备维护窗口

等待活动运行、文档入库和导出任务结束，确认没有正在进行的部署，在 `/data/semibrain/backups` 下选择一个新目录。

## 2. 执行冷备份

```shell
python3 scripts/ops/cold_recovery.py --output /data/semibrain/backups/<new-name> --maintenance-confirmed
```

脚本会关闭入口、停止 worker、再次检查未完成任务，计算权威 Mongo 集合和合成 Postgres 表的数据指纹，再停止存储并归档其绑定挂载目录。即使归档失败，也会重新启动在线服务。

## 3. 启动隔离恢复环境

脚本将备份恢复到新目录，启动独立的 Mongo、Redis、Postgres、MinIO、etcd、Milvus 和 Neo4j 容器，不发布端口，也不启动应用 worker。

不要将该网络连接到在线应用。**容器启动成功不等于恢复验证成功。**

## 4. 验证恢复结果

```shell
python3 scripts/ops/verify_recovery.py --backup /data/semibrain/backups/<new-name>
```

脚本验证以下内容：

- 比较权威数据指纹。
- 验证 Redis 认证。
- 校验对象内容哈希，以及私有文档的访问拒绝行为。
- 从恢复后的正文重建一份代表性文档的向量投影，并执行真实检索。
- 重建完整图谱拓扑。

脚本记录已测试范围，并在 `finally` 中停止演练容器，保留归档和恢复后的文件，供运维检查。

## 5. 维护后检查

检查在线健康端点、登录页和一条历史回答。停机时长与恢复/验证耗时分别记录。

检查 `verified.json`。只重建了一份代表性文档投影时，不能声称已经完成全量向量重新嵌入；其余向量数据由冷快照原样恢复。

## 应用回滚与灾难恢复的区别

应用和存储镜像固定到原始摘要。存储恢复不执行应用 schema 迁移。

应用版本回滚独立进行：恢复先前的镜像/配置引用，同时保留兼容数据。实际灾难恢复需要明确选择恢复点、恢复到新位置、完成验证，再由运维批准切换。上述脚本不会覆盖在线数据或重定向流量。

## 验证范围

| 项目 | 当前边界 |
| --- | --- |
| 演练位置 | 同一主机上的独立 Docker 环境，不是第二台主机的故障恢复演练 |
| 已下载文件 | 无法追溯撤销用户设备中的副本 |
| 外部服务 | 外部模型、搜索提供方及 Langfuse 不纳入备份 |
| 临时状态 | 队列与短期授权条目可能在恢复后正常过期 |
| 异机保护 | 需另外建立异机副本；本地验收应记录是否具备 |

验收记录应明确以上边界及实际完成的验证范围。
